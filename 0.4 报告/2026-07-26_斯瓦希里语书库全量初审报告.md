# Soma 斯瓦希里语书库全量初审报告

审查日期：2026-07-26  
范围：`0.0书籍正文/` 下 11 本书、11 份 `story_meta.json`、11 份斯瓦希里语 Markdown 正文及其章节结构。  
本轮为只读初审；未改动正文、元数据或线上草稿。

## 结论

- 判定：**全部需要修订后才能作为正式公开内容导入。**
- 阻断问题：P0 共 7 类，覆盖结构、公开残留、元数据与译文完整性。
- 核心原因：正文不是经过母语编辑的出版稿，存在明显逐句机器直译、中文残留、专名不一致、章节结构不统一，以及面向肯尼亚读者所需的文化说明缺失。
- 处理原则：故事背景仍应保留为中国都市或西方奇幻；不把人物、货币、WeChat、地名强行改成肯尼亚设定。对读者陌生但影响理解的概念，首次出现时以自然的斯瓦希里语补足说明。

## 审查方法与边界

1. 全量核对文件、封面、元数据字段、章节编号、Markdown 标题层级、可导入性、中文/英文残留和公开声明。
2. 审阅每部开篇、章节衔接点和结尾，重点检查叙事人称、专名、文化项、恐怖/暴力内容标识及译文是否像自然斯瓦希里语。
3. 本报告不对中文原稿的史实、医学、法律或技术事实作真实性背书；后续精修以原文为准，不擅自改写剧情。

## P0 阻断问题

### P0-S01：章节 Markdown 不能稳定被导入器识别

- 证据：`为爱冲锋…` 使用 `#Malipo…`（缺空格）及 `## Sura`；`月华下…` 只有 `## Sura`；`第30次丧尸循环…` 使用 `#Sura ya 1`（缺空格）；`气压杆…` 同时有重复 H1 与 H2 章节。
- 影响：当前导入器按一级 `# Sura` 拆章，格式混用会导致章节被并入、误切或标题遗失。
- 修复：统一为“书名 H1 + `## Sura ya N: 标题`”的出版 Markdown；同步更新导入脚本，使其仅从 H2 章节标题拆章。
- 验证：每本书的实际章节数与 `story_meta.json` 一致；构建 JSON 后章节标题、顺序与字数均正确。

### P0-S02：章节数、章节标题和正文不一致

- `月华下的永生契约`：元数据写 16 章，正文可识别章节标题只有 11 个，且元数据含重复的第 1、4 章条目。
- `血月古堡的囚徒新娘`：元数据写 6 章，正文只有第 1—5 章。
- `为爱冲锋？…`：元数据写 10 章，正文标题层级与缺失情况不一致。
- `二手冰柜里的第37份外卖`、`气压杆里的骨头`：元数据缺少可用的章节数组与完整章节数。
- `第30次丧尸循环…`：10 个元数据章节标题均为空。
- 修复：先以源稿确定真实章节边界，再补齐或校正元数据；不得用推测补写缺失正文。

### P0-S03：公开稿包含内部 AIGC/追踪信息与免责声明

- 证据：`二手冰柜…`、`永夜狼吻` 顶部含 AIGC、生产/传播 ID、保留码；两书结尾仍有“AI 生成内容，仅供参考”一类声明。
- 影响：暴露内部追踪信息，降低读者信任，也不应成为小说正文的一部分。
- 修复：从公开正文中移除全部 AIGC 块、保留码和免责声明；如需要合规存档，另存内部元数据文件。
- 验证：公开 Markdown 和导入 JSON 均不含 `AIGC`、`ReservedCode`、`Maudhui yanayotokana na AI`。

### P0-L01：存在未翻译的中文段落与中文统计表

- `旧手机里的前女友…` 第 10 章约第 1617 行起仍为连续中文结尾段落。
- `入殓师的剪刀…` 第 8 章约第 1080 行保留一段中文推理；结尾还有“Idadi ya maneno”表，但表头仍写“中文字符”。
- `二手冰柜…`、`气压杆…` 各有中文单字残留。
- 修复：逐段按中文原稿复译，删除不属于阅读正文的统计表；建立“零中文字符”检查（专名引用除外）。
- 验证：正文中不再有汉字；章节内容能在斯瓦希里语环境中连续阅读。

### P0-L02：关键人名被误译为普通斯瓦希里词，且同一人物多种拼写

- 证据：`旧手机里的前女友…` 将游四两写成 **Wewe Siliang**；`气压杆…` 在 You Qian / Wewe Qian 间摇摆；`永夜狼吻` 出现 Serafina / Seraphina、Orderric / Odric、Lucian / Lucien；`血月古堡…` 同时出现 Bloodmoon Castle 与 Ngome ya Mwezi wa Damu。
- 影响：`wewe` 在斯瓦希里语中意为“你”，会直接破坏人物辨识与叙事沉浸。
- 修复：每本建立角色、地名、组织、器物术语表；采用一套拉丁字母转写，全文替换并人工复核。
- 验证：同一实体只保留一个规范写法；代词不会与姓名混淆。

### P0-L03：大量直译句法和英语/中文术语混杂，未达到可出版的斯瓦希里语自然度

- 证据：多书反复出现中文式短句堆叠、主谓不一致、时态摇摆、错误搭配，如“Yeye kutembea kwa njia ya heather”“vampire crouched…”，以及 `Witcher Bloodline`、`Silver Moon`、`Bloodmoon Castle` 等未经策略处理的混用。
- 影响：肯尼亚读者会频繁停顿，且恐怖、悬疑、言情的节奏被破坏。
- 修复：按书逐章母语级重译/重写，优先修复叙事人称、动词时态、对白、动作链和逻辑连接，不改剧情事实。
- 验证：每章通读无中文句法痕迹；外来专名只按术语表保留，不出现随机英语。

### P0-M01：一部书的结尾有重复追加内容

- 证据：`为爱冲锋？…` 已出现“(Kitabu kamili)”后，又追加一段与前文重复的结局场景。
- 修复：依据源稿保留唯一结尾；删除重复段。
- 验证：全文只有一个结局标记，结尾与最后章节标题一致。

## 文化背景与内容分级规范

- **不做错误本地化**：人民币、WeChat、公安/刑侦、地铁、城市村、家族称谓均属于故事世界，应保留中国背景。首次出现时以简洁斯瓦希里语说明，例如“yuan (RMB, sarafu ya China)”和“WeChat, programu ya ujumbe ya China”。
- **避免把网络俚语逐字翻译**：`绿茶`、`渣男`、`疯批`、`追妻火葬场` 需按场景译为操控型情人、虚伪的第三者、危险而偏执的人物、迟来的追悔等，而非保留中文网文标签。
- **分级与警示**：殡仪/器官/血腥案件、丧尸肢解、精神控制、家庭暴力、强制关系应在书籍详情页和导入元数据中提供简短内容警示；不应把“校花”处理为未成年暗示。

## 修订顺序

1. **阶段 A：结构与公开残留（全 11 本）**：删除 AIGC/统计残留、统一 Markdown、建立章节和元数据对照表；不改剧情。
2. **阶段 B：专名与文化术语（全 11 本）**：每书建立术语表，统一姓名、地名、货币、App、机构和奇幻种族。
3. **阶段 C：语言精修（逐书逐章）**：优先处理含中文残留及格式失效的 9 本，再处理两本结构相对完整但仍需重译的作品。
4. **阶段 D：复核与重新导入**：零中文、零内部声明、章节数一致、封面 URL 有效、内容警示/分类完整后，才重新上传草稿并人工抽读。
